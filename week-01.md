# Week 1 — Java 8 → 17 migration

My research focuses on evaluating JetBrains' coding agent Junie for migrating Java repositories from version 8 to 17, in comparison with existing code migration tools. This week, I examined two benchmarks for Java migration, as well as Google's approach to the process. In the FreshBrew [1] study, a CodeAct agent, tested with nine different LLMs, successfully migrated up to 52% of 228 projects, whereas OpenRewrite managed 7%. In MigrationBench [2], an agent powered by Claude 4.5 Sonnet migrated 72% of the projects, compared to 16% for OpenRewrite. Google [3], in its large-scale industrial migrations, validates every LLM-generated change through builds, automated testing, and human review. Building on this, I plan to evaluate Junie with different LLMs and repeated runs and compare it with tools like OpenRewrite.

To understand how to run OpenRewrite and Junie, and to verify that they function as expected, I wrote a small script and tested both tools on a single, compact repository from the MigrationBench dataset: `springfox-loader` (a Spring Boot project with 17 tests). The script builds the project using both JDK 8 and JDK 17, applies the OpenRewrite `UpgradeToJava17` recipe, and then rebuilds the project using JDK 17. For now, I have defined a "successful" migration as one where the `mvn clean verify` command, which compiles the project and executes its tests, completes successfully, with the classes compiled for Java 17. However, these success metrics may be refined in the future. While OpenRewrite did successfully upgrade the Java version and the plugins, the tests failed: the older version of Spring is unable to read Java 17 class files, and the OpenRewrite recipe does not include the functionality to update Spring itself. In a single run via the CLI, Junie automatically built the project several times, analyzed errors, and updated Spring Boot (from 2.1 to 2.7), Spock, JaCoCo, and various Maven plugins, resulting in all 17 tests passing, although the Groovy test classes were still compiled for Java 8. The process took about 2.5 minutes and cost approximately $0.04. Moving forward, I plan to test both tools on a larger set of repositories.
